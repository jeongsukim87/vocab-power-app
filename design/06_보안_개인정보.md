# 6. 인증 · 보안 · 개인정보

## 6-1. 인증

| 항목 | 구현 |
|---|---|
| 계정 발급 | 교사가 학생 계정(아이디 + 1회용 초대 코드) 발급. 초대 코드는 **발급 화면에서만** 한 번 보이고, 서버에는 해시만 남는다. 유효기간 14일 |
| 최초 등록 | 학생이 로그인 화면 «처음 오셨나요?» 에서 아이디·초대 코드·새 비밀번호 입력. 코드는 즉시 폐기 |
| 비밀번호 | 평문 저장 없음. `SHA-256(소금 + 서버 비밀값 + 비밀번호)` 를 1만 번 반복한 값만 저장. 학생 6자·교사 10자 이상, 아이디와 같거나 한 글자 반복은 거절 |
| 로그인 보호 | 5회 연속 실패 시 10분 잠금. 없는 아이디도 같은 메시지·비슷한 시간(존재 여부 노출 방지) |
| 세션 | 무작위 토큰. 서버에는 **토큰의 해시**만 저장. 학생 8시간·교사 4시간 후 만료(최대 24시간). 로그아웃·비밀번호 변경 시 서버에서 폐기 |
| 계정 복구 | 교사가 «새 코드» 를 주면 기존 로그인을 모두 끊고 새 비밀번호를 만들게 한다. 교사 계정은 Apps Script 편집기에서 `newTeacherCode()` |
| 이름만으로 접근 | 불가능. 이름은 표시용일 뿐 로그인에는 아이디+비밀번호가 필요 |

## 6-2. 권한 검사 (모든 엔드포인트, 서버에서)

1. 토큰 → 세션 → 사용자(`ACTIVE` 만).
2. 엔드포인트의 요구 역할(`student` / `teacher` / `any`) 확인 → `FORBIDDEN`.
3. 학생: 대상 행의 `user_id` 가 본인인지 확인, 아니면 «없음(NOT_FOUND)».
4. 교사: 학생의 학급이 `teacher_id = 본인` 인지 확인.
5. 교사가 학생 기록을 열람·내보내기·백업하면 `AuditLogs` 에 남긴다.

Apps Script 웹앱은 «누구나 접근» 으로 배포해야 학생이 구글 로그인 없이 쓸 수 있으므로 **주소 자체는 공개**다.
그래서 위 검사를 코드가 직접 한다. `tests/run_tests.html` 이 학생 A→B, 교사 간, 비로그인 접근을 자동으로 시도해 막히는지 확인한다.

## 6-3. 개인정보

- **받는 정보**: 이름(교사가 입력), 번호, 아이디, 암호화한 비밀번호, 학습 기록(글·뜻 설명 등). 전화번호·개인 이메일·주민등록번호·생년월일은 받지 않는다.
- **외부 전송**: 화면은 GitHub Pages(정적 파일)와 Apps Script 서버만 부른다. 글꼴(Google Fonts)과 엑셀 내보내기 도구(cdnjs)를 불러오는 것 외에 외부 서비스로 학생 정보를 보내지 않는다. **외부 AI API 는 쓰지 않는다.**
- **보관·삭제**: 학년이 끝나면 «자료·백업» 에서 내려받기·백업 후 «학생 삭제»(계정과 모든 기록 삭제, 되돌릴 수 없음). 자동 삭제는 하지 않는다(교사가 결정).
- **접근 기록**: 로그인, 계정 발급·복구·삭제, 학생 기록 열람, 내보내기, 백업.
- **GitHub 저장소에는 학생 정보를 올리지 않는다.** 저장소에는 코드와 공개 가능한 어휘 데이터만 있다. 구글 시트 주소·`config.js` 의 서버 주소는 비밀번호가 아니지만, 시트 자체는 선생님 계정 안에서만 공유하고 **다른 사람에게 편집 권한을 주지 않는다.**
- 백업 파일(JSON)에는 학생 이름과 암호화된 비밀번호가 들어 있다. 개인 드라이브처럼 안전한 곳에만 보관한다.

## 6-4. 화면 쪽 보안

- 학생이 쓴 글은 모두 **이스케이프**해서 화면에 넣는다(`UI.html` 템플릿). 글에 `<script>` 를 넣어도 실행되지 않는다.
- 내보내기 파일에서 `= + - @` 로 시작하는 칸은 앞에 `'` 를 붙여 엑셀 수식으로 실행되지 않게 한다.
- 로그인 토큰은 `sessionStorage`(탭을 닫으면 사라짐)에 둔다. 쓰던 글의 임시 보관본은 `localStorage` 에 있으며 저장에 성공하면 지운다.
