## 2-2. 권장 — Apps Script + 구글 시트 + GitHub Pages

- **화면(정적 파일)** 은 GitHub Pages 에 올려 학교 밖에서도 열 수 있게 한다.
- **저장 서버** 는 선생님 구글 계정의 Apps Script 웹앱 + 구글 시트 한 개. 학생 계정은 **구글 계정이 아니라 앱 자체 계정**이다.
- 이유: ① 설명서의 우선 검토안이며 ② 학생이 구글 계정이 필요 없고 ③ 선생님이 시트로 데이터를 직접 확인·백업할 수 있으며 ④ 비용이 없다.

### 한계(정직하게)

- 쓰기 요청은 `LockService` 로 **줄을 세워** 처리한다. 한 요청이 0.3~1초라면 학급 전원(30명)이 같은 순간에 저장해도 수십 초 안에 끝나지만, **수백 명이 동시에 쓰는 대규모 상황**에는 맞지 않는다.
- 구글의 실행 시간·동시 실행·하루 호출 수 제한(구글 정책에 따라 바뀜)을 따른다. 한 학년(100~200명)이 수업 시간에 나누어 쓰는 정도를 가정했다.
- 시트는 표 하나를 통째로 읽는다. 문장이 수만 줄을 넘으면 느려지므로 학년이 끝나면 **백업 후 새 시트**로 시작하길 권한다.
- 비밀번호 해시는 «소금 + 비밀값(pepper) + SHA-256 1만 번 반복» 이다. Apps Script 에는 bcrypt·PBKDF2 가 없어서 쓴 방식이며, 전문 인증 서비스보다 약하다. 그래서 **로그인 실패 잠금 + 짧은 세션 + 교사 발급 초대 코드**를 함께 쓴다.

### 대안으로 옮길 때

`backend/Core.gs` 는 저장소와 무관한 순수 로직이라, `store`(저장소) 인터페이스(`all/get/insert/update/remove`)만 다른 DB 에 맞춰 구현하면 된다.
체험 모드가 이미 메모리 저장소로 같은 Core 를 쓰고 있다(`docs/js/memory_store.js`).
